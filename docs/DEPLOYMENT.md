# Local setup and deployment

Use Node.js 20 and pnpm 9.14.2 (the version pinned in `package.json`). Install with `pnpm install --frozen-lockfile`. For a disposable local database, start Supabase with `supabase start`, then read its URL and keys with `supabase status`. Alternatively, point the two ignored `.env` files at an existing Supabase project. Copy `apps/api/.env.example` to `apps/api/.env` and `apps/web/.env.example` to `apps/web/.env`, replacing placeholders. The API needs `SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY`. Stripe credentials are optional for startup; billing endpoints requiring Stripe return 503 until configured. The web app needs `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, and `VITE_API_URL=http://localhost:3000`. Set `VITE_SHORT_URL_BASE=http://localhost:3000/r`. Keep the service-role key out of web variables.

Run `pnpm --filter @wrx/shared build`, then start `pnpm --filter @wrx/api dev` and `pnpm --filter @wrx/web dev` in separate terminals. Visit `http://localhost:5173`; check `http://localhost:3000/health` and `http://localhost:3000/docs`. The repository's `pnpm dev` starts all apps, including the unfinished mobile and extension packages, so the filtered commands are simpler for first local testing.

The local ignored environment files were configured for the hosted `wrx_generator_v2` Supabase project on 2026-10-02. They are not committed. The hosted schema is present, but its SQL Editor execution is not in CLI migration history; see `docs/DATABASE.md` before any future `supabase db push`. Authentication and billing configuration beyond the database schema should be verified separately before production deployment.

Before a merge, run `pnpm build`, `pnpm typecheck` and `pnpm test`. CI runs one 15-minute job only for code changes in pull requests targeting `main`, or when started manually. Documentation-only changes do not trigger CI. Automatic deploy and release workflows were disabled; deployment requires a manual workflow run and configured hosting secrets. Review the deploy workflow and target environment before using it; it has not been verified against live hosting.
