# CI/CD

`.github/workflows/ci.yml` runs one Ubuntu job for pull requests targeting `main` when API, web, shared packages, migrations, manifests, or CI configuration change. It installs dependencies, builds the shared package, API and web app, checks API and web TypeScript, and runs web unit tests. It uses Node 20 and pnpm 9.14.2, cancels superseded runs on the same PR, and has a 15-minute timeout. It can also be started manually. Markdown-only changes and ordinary pushes do not start CI. Mobile and extension changes need local checks; they are outside this economical automatic gate.

Dependabot PRs are skipped by the automatic job; review and test them locally or run the workflow manually when you intend to merge one. Browser E2E, coverage uploads and release publishing are deliberately outside this automatic workflow to conserve GitHub Actions minutes. Run browser tests locally when changing user flows. `.github/workflows/deploy.yml` is manual only and requires hosting configuration and secrets; it has not been validated against a live target. The previous release workflow referenced missing release scripts and a missing Dockerfile, so it was removed.

To merge safely, open a PR from `develop` into `main`, review its single CI result and changes, then merge. A direct push to `main` does not trigger CI or deployment. Configure branch protection in GitHub if you want PR review and a passing CI check to be mandatory; repository files alone cannot enforce that setting.
